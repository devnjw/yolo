# FocusTrace

Mac에서 사용 중인 모든 전면 앱과 지원 브라우저의 웹사이트 사용 시간·방문 횟수를 기록하는 SwiftUI 앱입니다. 서비스를 사용자 정의 카테고리로 분류하고 전체 또는 선택한 카테고리의 사용 패턴을 볼 수 있습니다. 기록은 Mac에 저장되며 계정이나 서버가 필요하지 않습니다.

## 빌드와 실행

- 실행: macOS 13 이상
- 빌드: macOS, Swift 6.0 이상과 macOS SDK (Xcode 16 이상 또는 해당 Command Line Tools)
- 외부 패키지 의존성 없음. 기록 저장에는 macOS에 포함된 SQLite 사용

```sh
git clone https://github.com/devnjw/yolo.git
cd yolo
swift test
zsh build.sh
open dist/FocusTrace.app
```

빌드 스크립트는 아이콘을 생성하고 현재 Mac 아키텍처용 실행 파일을 `.app`으로 묶어 ad-hoc 서명합니다. **실행 중인 FocusTrace를 종료한 후 빌드하세요.** Developer ID 서명·공증을 거친 배포용 빌드는 아닙니다. Swift 패키지는 Swift 5 언어 모드를 사용합니다.

## 사용법

1. 앱을 실행하면 추적이 시작됩니다. 창을 닫아도 메뉴 막대에서 계속 동작하며, 메뉴 막대의 **Quit FocusTrace**로 종료합니다.
2. 전면에서 사용하는 앱과 사이트는 **Services**에 자동으로 추가됩니다. 같은 서비스의 앱·도메인은 한 행으로 묶이며, 행 어디든 누르면 오른쪽 편집 패널에서 구성원과 사용량을 확인하고 표시 이름을 수정할 수 있습니다. 테이블의 카테고리는 읽기 전용이며, 편집 패널의 **Category**에서 검색해 카테고리를 지정하거나 **New category…**로 만들면서 바로 지정할 수 있습니다. 더보기의 **Add service…**로 아직 사용하지 않은 대상을 미리 추가할 수도 있습니다.
3. 웹사이트별 기록은 **Settings → Website tracking**을 켜고 Chrome·Safari를 선택해야 합니다. 모든 HTTP/HTTPS 사이트를 자동 등록하며, 주소를 읽을 수 없는 탭이나 다른 브라우저는 브라우저 앱 사용 시간으로 기록합니다. 앱과 사이트 시간을 중복으로 더하지 않습니다. 활성 브라우저의 프로세스 ID로 탭을 조회하므로 자동화용 Chrome이 별도로 실행되어도 서로 혼동하지 않으며, 조회 중 활성 프로세스가 바뀌면 이전 응답은 폐기합니다. macOS가 요청하면 자동화 접근을 허용합니다. 화면 녹화·손쉬운 사용 권한이나 확장 프로그램은 필요하지 않습니다.
4. **Overview**의 기본 보기는 **All categories**입니다. 전체 시간과 Visits, 카테고리별 내역을 한 번에 표시합니다. 시간 위의 카테고리 선택에서 하나 또는 여러 개를 고르면 해당 기록만 집계하며 선택은 재실행 후에도 유지됩니다. 왼쪽에 요약·시간 그래프, 오른쪽에 독립적으로 스크롤되는 사용 목록을 배치합니다. 좁은 창에서는 세로 배치로 전환합니다. 오른쪽 목록 상단의 **Categories / Services** 텍스트 탭으로 카테고리별 합계 또는 개별 서비스 순위를 볼 수 있으며 보기 방식은 재실행 후에도 유지됩니다. **All categories + Services**에서는 카테고리로 묶지 않은 전체 서비스 사용 시간·방문 횟수를 사용 시간순으로 표시합니다. 카테고리 필터와 날짜·기간은 두 보기에서 동일하게 적용됩니다. 카테고리 행을 누르면 해당 카테고리의 Services 보기로 이동합니다. 서비스 행을 누르면 왼쪽 시간 그래프와 상단 시간·Visits가 해당 서비스 기준으로 바뀌며 선택한 행이 강조됩니다. 같은 행을 다시 누르거나 그래프 위의 선택 해제 버튼을 누르면 카테고리 전체로 돌아옵니다. 날짜·기간을 바꿔도 서비스 선택은 유지되며 카테고리를 바꾸면 해제됩니다. Day는 합계, Week·Month·Year는 기록 근거가 있는 완료된 날짜의 하루 평균입니다. 오늘과 기록이 없는 날짜는 평균에서 제외하고 다른 활동만 있었던 날짜와 기록 근거가 있는 0분 날짜는 포함합니다. 카테고리·서비스 내역과 상단 값 모두 같은 분모를 사용합니다. Year의 월별 막대도 하루 평균이며 연간 값은 날짜 수로 가중합니다.
5. 기간 탭과 날짜 이동으로 범위를 고릅니다. 그래프는 Day의 시간별, Week·Month의 일별, Year의 월별 활동을 보여줍니다. 막대를 누르면 서비스 목록이 해당 구간으로 좁혀지고 상단 값은 유지됩니다. 서비스 선택은 전체 기간의 그래프를 필터링하며 목록의 다른 서비스를 눌러 바로 전환할 수 있습니다. 현재 날짜의 일별 막대는 진행 중인 합계를 표시합니다. 데이터가 없는 구간은 0분과 구분합니다.
6. **Services**는 기간과 관계없는 전체 서비스 테이블입니다. **Name · Type · Category · Total visits · Total time spent** 헤더를 누르면 기본 방향 → 반대 방향 → 정렬 해제 순서로 전환됩니다. 이름·유형·카테고리는 오름차순, 사용량은 내림차순부터 시작하며 정렬 해제 시 화살표 없이 기본 이름순으로 돌아갑니다. **Filter**에서 유형과 카테고리를 함께 선택하고, 서비스 이름·앱 식별자·도메인·별칭 검색과 조합할 수 있습니다. 정렬·필터 설정은 재실행 후에도 유지됩니다. 유형은 **App / Web / App & Web**으로 구분하며, App & Web은 앱과 웹이 하나로 묶인 서비스입니다. 유형 필터는 이 세 유형 중 하나를 선택합니다. 이름·유형·카테고리·사용량을 포함한 행 전체를 누르면 목록 옆에 편집 패널이 열리고, 선택된 행을 다시 누르면 닫힙니다. 목록과 패널 사이 구분선을 드래그해 폭 비율을 조절할 수 있으며, 조절한 비율은 재실행 후에도 유지됩니다. **Name → Save**로 표시 이름을 바꾸고, 패널의 **Merge with another service…**에서 대상 하나를 검색해 병합합니다. 결과 이름과 카테고리를 확인한 뒤 **Merge services**로 적용하며, 서로 다른 카테고리는 직접 하나를 선택해야 합니다. 여러 앱·웹사이트가 병합된 서비스에만 **Apps & websites** 목록이 표시되며, 분리 버튼으로 구성원 하나를 별도 서비스로 옮길 수 있습니다. 분리한 서비스는 기존 카테고리를 물려받고 다시 자동 병합되지 않습니다. 이름·병합 관계·카테고리는 함께 저장되며 과거와 이후 사용량에 적용됩니다. 체크박스 일괄 선택과 실행 취소 기능은 제공하지 않습니다. ChatGPT와 Codex는 기본적으로 별도 서비스로 구분됩니다. 누적 값은 이 Mac에서 FocusTrace가 기록한 전체 이력과 현재 방문을 합산하며, 기록 시작 전·추적 중단 기간은 포함하지 않습니다. Overview의 날짜·카테고리 선택과 독립적입니다. 원본 기록은 그대로 보관하고 메모리 집계를 변경분만 갱신하므로 정렬할 때 전체 방문 기록을 다시 읽지 않습니다. **Settings → Privacy & data → Export all records…**의 CSV 내보내기는 필터에 관계없이 전체 원본 기록과 현재 카테고리 이름을 포함하며 시각은 UTC ISO 8601입니다.
7. 사이드바의 **Settings** 페이지는 **General · Categories · Privacy & data**로 구성됩니다. **Settings → Categories** 또는 Services의 **Manage categories…**에서 카테고리를 추가·수정·삭제할 수 있습니다. 추가·수정 시 기본 색상 10개 또는 macOS 색상 선택기로 직접 색을 지정할 수 있으며, 그래프와 목록에 함께 반영됩니다. 기본값은 **Work, Learning, Communication, Social, Entertainment, Personal**이며 모두 사용자 카테고리처럼 수정·삭제 가능합니다. 카테고리를 삭제할 때 다른 카테고리나 **Other**로 서비스를 옮깁니다. Other는 미지정 상태이며 이름과 색상을 수정할 수 있지만 삭제할 수 없습니다.

새 서비스는 Other에서 시작합니다. 기존 서비스의 새 앱·도메인이면 서비스의 카테고리를 이어받습니다. 서비스마다 카테고리는 하나이며 변경하면 과거·향후 기록의 분류가 함께 바뀝니다. 기록 자체를 수정하거나 수집을 중단하지 않습니다. 앱과 웹을 서로 다른 목적으로 쓰는 경우까지 자동 판별하지 않습니다.

유명 서비스는 최초 발견 시 기본 카테고리를 지정합니다. ChatGPT·Claude·Notion·GitHub·Figma는 Work, 학습·논문 사이트는 Learning, Slack·카카오톡·메일은 Communication, Instagram·LinkedIn·X는 Social, YouTube·Spotify는 Entertainment, 쇼핑·일정 서비스는 Personal로 시작합니다. 이는 변경 가능한 초기값이며 실제 사용 목적을 추정하지 않습니다. 브라우저·일반 검색·알 수 없는 서비스는 Other로 남습니다. 도메인 경계와 정확한 앱 식별자로만 판별하며 이름·별칭은 사용하지 않습니다.

기존 **Distractions**는 제거하고 해당 서비스와 아직 지정하지 않은 유명 서비스에 초기 분류를 적용합니다. 사용자 지정 카테고리와 기존 지정값은 유지합니다. 명시적으로 Other를 선택한 경우도 저장하여 자동 분류가 덮어쓰지 않습니다. 삭제한 기본 카테고리는 다시 생성하지 않습니다. 방문 원본은 변경하지 않고 현재 분류로 집계합니다.

Overview의 누적 막대·목록·카테고리 선택은 Apple Screen Time을 참고한 선명한 파랑·청록·주황 계열 팔레트를 공유하며, 밝은 모드에서는 대비를 위해 더 짙은 색을 사용합니다. 중립적인 배경과 절제된 강조색은 [Linear의 UI 디자인 글](https://linear.app/now/how-we-redesigned-the-linear-ui)을 참고했습니다.

헤더는 macOS 기본 툴바를 사용하며 사이드바와 같은 배경으로 이어집니다. 기본 macOS 창 제어 버튼 옆의 사이드바 버튼 또는 **⌃⌘S**로 탐색 영역을 접고 펼칠 수 있으며 상태는 저장됩니다. 사이드바는 별도의 로고 행 없이 탐색 메뉴부터 시작하고, 본문 패널의 상단 여백은 8pt로 맞춥니다. 헤더에는 현재 페이지와 해당 화면의 동작만 배치하고, Overview의 기간·날짜 이동을 한 묶음으로 정렬합니다. 버튼은 네이티브 툴바 안에 배치해 더블클릭이 창 확대 동작으로 전달되지 않게 하고, 빈 헤더 영역의 창 이동·더블클릭 동작은 macOS가 처리합니다. 밝은 모드와 어두운 모드 모두 탐색 배경과 본문 패널을 구분하며, Settings도 다른 메뉴와 같은 선택 표시를 사용합니다.

이 구성은 첨부된 Linear·Codex·Slack 화면과 다음 공식 자료를 비교해 정했습니다. [Linear의 UI 재설계](https://linear.app/now/how-we-redesigned-the-linear-ui)는 헤더·사이드바의 정렬, 탐색 밀도, 시각적 잡음 감소를, [Notion의 사이드바 안내](https://www.notion.com/help/navigate-with-the-sidebar)는 접기·펼치기를, [Craft의 사이드바 개선](https://www.craft.do/blog/craft-update-3-4-2)은 항목 숨기기와 정렬을 설명합니다. FocusTrace는 메뉴가 세 개뿐이므로 다단계 워크스페이스·검색·장식용 메뉴를 추가하지 않고, 얇은 공통 헤더와 접을 수 있는 단일 탐색 영역에 적용했습니다. 창 제어는 시스템 버튼을 유지하며 [Apple의 툴바 지침](https://developer.apple.com/design/human-interface-guidelines/toolbars)에 맞춰 창 상단에 통합합니다.

**Settings → Launch at login**은 macOS `SMAppService`로 자동 실행을 등록합니다. 등록한 앱의 위치를 유지하세요. 브라우저 접근이 거부되면 시스템 설정 → 개인정보 보호 및 보안 → 자동화에서 허용한 뒤 해당 브라우저의 **Retry**를 누릅니다. 로컬 서명이 바뀌면 macOS가 권한을 다시 요청할 수 있습니다.

## 측정 기준

- 앱이나 사이트로 전환하면 방문 1회입니다. 같은 사이트 안의 페이지 이동은 같은 방문입니다. 서비스로 묶어도 원본 방문을 합치거나 다시 쓰지 않으므로 같은 서비스의 앱↔웹 전환은 각각의 방문으로 남습니다. Overview의 시간·방문 수는 구성원 기록의 합계입니다.
- 서비스 통합은 명시적인 앱 bundle ID와 도메인 목록을 사용합니다. ChatGPT, Figma, GitHub, Instagram, LinkedIn, Notion, Slack, Spotify, VS Code, YouTube를 인식하며, 목록에 없는 서비스는 개별 항목으로 유지합니다. 비슷한 이름만으로 자동 병합하지 않으며, Services의 편집 패널에서 수동 병합·분리할 수 있습니다. 같은 서비스의 구성원은 하나의 카테고리를 공유합니다.
- 약 1초 간격으로 전면 앱·활성 탭을 확인합니다. 수 초의 경계 오차나 짧은 방문 누락이 있을 수 있으며, 실제 시선이나 업무 목적을 판단하지 않습니다.
- 기본값은 5분간 입력이 없으면 그 시점부터 중단합니다. 앞선 5분은 포함됩니다. 영상 시청처럼 입력 없는 이용도 제외될 수 있으며 Settings에서 기준을 바꿀 수 있습니다.
- 잠자기·화면 잠금·비활성 세션에서는 중단합니다. 지연된 샘플 사이의 긴 시간을 채워 넣지 않습니다. 약 5초마다 저장하므로 비정상 종료 시 최근 기록 일부가 유실될 수 있습니다.
- 방문 횟수는 시작 날짜에 귀속하고 시간은 날짜별 겹치는 구간으로 나눕니다. 날짜는 Mac의 현재 시간대 기준이며, 서머타임의 반복 시간은 같은 시간대 막대에 합칩니다.
- Quick checks는 종료된 방문 중 전체 길이가 30초 이하인 기록입니다. 진행 중인 방문은 제외합니다.
- 사이트는 실제 호스트명으로 자동 등록하며 `www.`와 마지막 점을 정규화합니다. `meet.google.com`처럼 별도 호스트는 상위 도메인에 합치지 않고 따로 기록하며, 정확히 일치하는 기존 호스트 또는 별칭의 ID를 재사용합니다. 알려진 서비스의 통합 표시는 수집과 별도로 적용합니다. localhost·IP 주소도 기록합니다. 브라우저 앱의 카테고리는 사이트로 분리되지 않은 앱 시간에만 적용됩니다. 과거에 상위 도메인으로 합쳐진 기록에는 원래 호스트가 남아 있지 않으므로 자동으로 재분리하지 않습니다.
- 시크릿 창도 브라우저가 활성 탭 주소를 제공하면 측정됩니다. 시크릿 창 자동 제외 기능은 없습니다.

## 데이터와 개인정보

`~/Library/Application Support/FocusTrace/`에 저장합니다.

| 파일 | 내용 |
| --- | --- |
| `recording.sqlite3` | 방문 ID·대상 ID·시작/종료 시각과 관측 구간. 현재 기록의 원본 |
| `visits.json`, `coverage.json` | 이전 버전의 방문·관측 구간. 최초 가져오기 후 보존하며 갱신하지 않음 |
| `sources.json` | 이름, 앱 식별자 또는 사이트 호스트, 별칭, 이전 버전과의 호환을 위한 방해 여부·제외 상태 |
| `categories.json` | 카테고리 정의·색상, 서비스별 지정·표시 이름·병합/분리 설정, Overview 선택. 한 파일에 원자적으로 저장 |

이전 버전의 문자열 ID와 Foundation JSON 날짜 형식을 그대로 읽습니다. 첫 실행에서 기존 방문과 관측 구간을 하나의 SQLite 트랜잭션으로 가져오며 ID·시각·원본 순서를 보존합니다. 완료 표시도 같은 트랜잭션에 기록하므로 실패 후 재시도할 때 중복 가져오지 않습니다. 이전 JSON은 삭제하거나 덮어쓰지 않습니다. 가져오기 이후에는 SQLite가 기록의 원본이며, 남아 있는 JSON은 이전 시점의 백업입니다. 이전 앱으로 돌아가면 새 SQLite 기록은 표시되지 않습니다.

폴더는 `0700`, 파일은 `0600` 권한으로 저장합니다. SQLite는 기본 rollback journal을 사용하며 저장 트랜잭션이 완료되면 임시 journal을 제거합니다. 읽기·기록 오류가 발생하면 추적을 중단하고 기존 파일을 보존합니다. categories 파일을 읽을 수 없어도 기본값으로 덮어쓰지 않습니다. **백업은 앱을 종료한 뒤 데이터 폴더 전체를 복사하세요.** 방문 기록과 기록일 정보를 초기화하려면 앱 종료 후 `recording.sqlite3`, 이전 `visits.json`, 이전 `coverage.json`을 함께 제거합니다. JSON을 남겨두면 다음 실행에서 이전 기록을 다시 가져옵니다.

이전 버전에서 coverage 파일이 없는 날짜는 기존 방문 기록을 기록 근거로 사용합니다. 이는 하루 전체 수집을 보증하지 않으며, 과거에 선택된 서비스만 수집한 기록은 그대로 제한된 범위입니다. 기록이 없던 과거 날짜를 0분으로 소급 생성하지 않습니다.

전체 URL은 메모리에서 대상 분류에만 사용하며 사이트 호스트만 저장합니다. bundle ID가 없는 앱은 실행 파일 경로를 식별자로 사용합니다. 페이지 제목·내용·메시지·스크린샷·키 입력 내용은 저장하지 않으며, 분석 SDK나 사용 기록 업로드 기능이 없습니다. 브라우저 설정은 UserDefaults에, 카테고리 선택은 categories.json에 저장됩니다.

앱 아이콘은 로컬에서 읽습니다. 웹사이트 아이콘은 해당 사이트의 공개 홈페이지·아이콘 주소에 HTTPS 요청으로 가져옵니다. 브라우저 쿠키·인증 정보는 사용하지 않으며, 제3자 아이콘 검색 서비스는 사용하지 않습니다. 아이콘 서버에는 일반적인 네트워크 요청 정보가 전달됩니다. 아이콘은 `~/Library/Caches/FocusTrace/WebsiteIcons/v2/`에 캐시하고, 실패하면 기존 캐시 또는 기본 아이콘을 표시합니다.

### 성능과 장기 보관

1초 측정 주기와 4초 초과 공백 제외 규칙은 유지합니다. 약 5초마다 변경된 마지막 방문·새 방문·관측 구간만 백그라운드 직렬 큐에서 트랜잭션으로 저장하며, 매번 전체 기록을 JSON으로 변환하지 않습니다. 저장 중 추가 요청은 합쳐 처리해 느린 디스크에서 작업이 무한히 쌓이지 않습니다. 정상 종료 때는 대기 중인 저장과 최신 방문의 완료를 기다립니다. 비정상 종료 시에는 마지막 저장 이후의 일부 기록이 유실될 수 있습니다.

메모리에서는 과거 기록을 256개 단위 불변 블록으로 공유하고 최근 블록만 변경합니다. 화면 갱신 때 전체 방문 배열을 복사하지 않으며, 블록별 시간 인덱스로 선택 기간에 해당하는 기록을 찾습니다. Overview는 같은 측정·기간·필터 상태의 결과를 재사용하고, 서비스별 누적값은 변경분만 갱신합니다. 측정 경계·자정·시간대·카테고리 선택 변경은 집계에 반영합니다.

시작할 때 전체 방문을 메모리로 읽는 구조는 유지합니다. 메모리와 시작 시간은 전체 기록량에 따라 증가하며, CSV 전체 내보내기도 전체 기록을 처리합니다. 자동 삭제·보관 기간 제한은 없습니다. 이 개선이 무제한 데이터 크기에서 일정한 메모리 사용량을 보장하지는 않습니다.

`Resources/AppIcon.png`가 앱 아이콘 원본이며 `scripts/build-icon.sh`가 `.icns`를 생성합니다. 빌드 산출물, 로컬 설정, 사용 기록은 Git에서 제외합니다.

## 검증

```sh
swift test
zsh build.sh
```

GitHub Actions에서도 테스트와 release 패키징·서명 검증을 실행합니다. 테스트는 실제 macOS 자동화 권한, 잠금·잠자기 이벤트, 로그인 자동 실행을 대신하지 않습니다. 이 동작은 빌드한 앱에서 확인해야 합니다.

대용량 성능 비교는 개인 기록 대신 방문 20만 건의 합성 데이터로 실행합니다. 시간은 CI 통과 기준으로 고정하지 않으며 결과의 합계와 저장 후 기록 일치를 검증합니다.

```sh
FOCUSTRACE_BENCHMARK=1 swift test -c release --filter PerformanceRegressionTests
```

2026-10-30 로컬 release 빌드에서 같은 합성 기록으로 비교한 예시입니다. 각 값은 3회 작업의 합계이며 시스템 부하에 따라 달라집니다.
